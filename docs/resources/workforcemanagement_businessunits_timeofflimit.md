# genesyscloud_workforcemanagement_businessunits_timeofflimit (Resource)

<!-- This document is automatically generated. Do not edit manually. Make changes to the schema, examples, or apis.md files in examples/resources/ and run 'make docs' to regenerate. -->

Genesys Cloud workforce management business unit time off limit, which limits the time off agents of a management unit or staffing group can take. Genesys Cloud allows one time off limit for each management unit and one for each staffing group, and it creates the id of the time off limit from theirs, so creating one that already exists fails: import it instead. Genesys Cloud cannot change a time off limit once it is created, so changing any attribute other than value_range drops the time off limit, with all of its values, and creates a new one. Deleting a time off limit purges its values in the background, so after a new time off limit replaces a deleted one the values are checked a few times and set again if they were purged.

## Schema

### Required

- `business_unit_id` (String) The id of the business unit this time off limit belongs to. Changing this attribute will cause the time off limit to be dropped and recreated.
- `granularity` (String) The granularity of the time off limit. Valid values: Daily, FifteenMinutes. Changing this attribute will cause the time off limit to be dropped and recreated.

### Optional

- `full_day_time_off_start_time` (String) The start time, in the format HH:mm, of the full day time off requests that count against this time off limit. It can only be set when the granularity is FifteenMinutes. Changing this attribute will cause the time off limit to be dropped and recreated.
- `management_unit_id` (String) The id of the management unit this time off limit applies to. Exactly one of management_unit_id and staffing_group_id must be set. Changing this attribute will cause the time off limit to be dropped and recreated.
- `staffing_group_id` (String) The id of the staffing group, at business unit or management unit level, this time off limit applies to. Exactly one of management_unit_id and staffing_group_id must be set. Changing this attribute will cause the time off limit to be dropped and recreated.
- `value_range` (Block List) Ranges of limit values to set. This is optional: the limit values can also be managed outside of Terraform, for example by import or in the UI. Only the ranges listed here are managed. Their values are set and checked for changes, and values on dates outside them are neither read nor changed. Removing a range from the configuration stops managing it and leaves its values as they are. Value ranges are not read when the time off limit is imported. Genesys Cloud only accepts and reads dates in a limited window around today. A range that has fallen outside the window can no longer be read, so it is kept as it is and not checked for changes, but it cannot be set again, for example when the time off limit is recreated, so remove ranges that are old from the configuration. At most 366 days of values are set in one request, so more are sent as several requests. (see [below for nested schema](#nestedblock--value_range))
